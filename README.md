# 计量器具检定与校准管理台

测量中心用来管计量器具的小台子：录器具台账、办检定与校准、看标准器、盯到期。

## 运行

```
npm install
npm start
```

默认端口 5189（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：器具总数与各状态台数、记录数、点数、不合格数、合格记录数、本月应检、已超期、最近到期。
- **器具**：台账的增删改查，看单条器具的到期日、宽限截止、剩余天数、历史检定与覆盖它的标准器、连续不合格标记。
- **检定记录**：录入与查询。一条记录带若干个检定点，每个点填标准值与示值，系统算误差、该点允许误差、并给出整条记录的结论。
- **标准器**：标准器的证书号、有效期、能覆盖哪些器具。
- **到期清单**：按到期日排的待检清单。

## 口径（这一版按下列规则实现，页面上的说明与数字都要与本段一致）

1. **单点允许误差**：按标准值在量程上的位置分两段。标准值**不到半量程**时，允许误差按「半个量程 × 准确度等级百分比」；标准值**达到或超过半量程**（边界归这一档）时，按「整个量程 × 准确度等级百分比」。等级百分比取 0.5 级 = 0.5%、1 级 = 1%、2 级 = 2%。半量程的分界比例记在设置里的 `segmentRatio`，默认 0.5。
2. **一条记录的结论**：**每一个点**都要落在它自己的允许误差内，整条才判合格；有任何一点超出自己的允许误差，整条判不合格。
3. **代表误差**：一条记录的代表误差取各点误差里**绝对值最大**的那一项。
4. **周期与到期**：到期日 = 上次检定日期 + 检定周期（**按自然月推**，不是按固定天数）。到期之后还有 `graceDays`（默认 15 天）的宽限，宽限内算「宽限内」，宽限结束仍未检定才算「已超期」。
5. **到期清单**：**所有器具都要出现在清单里**，包括停用、送检中与已报废的（这几类在清单里单独标注），并且**按到期日从近到远排列**；概览里的「最近到期」取的就是清单里最近的那一条。
6. **状态规则**：停用与已报废的器具**不能再登记新的检定或校准记录**，要先把状态改回在用。器具名下有检定记录时不能直接删除，只能改为停用或报废。
7. **连续不合格标记**：最近**两次**检定结论都是不合格，才算「连续两次不合格」。
8. **数字一致**：概览上的每个数字都要与相应列表里筛出来的条数一致（例如「不合格」要等于记录列表按结论不合格筛出来的条数）。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health | 健康检查 |
| GET | /api/summary | 概览数字 |
| GET / PATCH | /api/settings | 全局设置（基准单位、默认周期、宽限天数、分段比例） |
| GET | /api/departments | 部门清单 |
| GET / POST | /api/instruments | 器具清单（支持 keyword、status、category、deptId）/ 新增 |
| GET / PATCH / DELETE | /api/instruments/:id | 器具详情（含历史记录、覆盖标准器、连续不合格标记）/ 修改 / 删除 |
| GET / POST | /api/records | 检定记录清单（支持 instrumentId、kind、verdict、from、to）/ 新增（自动判定） |
| GET / DELETE | /api/records/:id | 记录详情（含逐点误差与允许误差）/ 删除 |
| GET / POST | /api/standards | 标准器清单 / 新增 |
| PATCH / DELETE | /api/standards/:id | 修改 / 删除 |
| GET | /api/due | 到期清单（支持 band 过滤） |

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。
